The graph (forced shape)

root  [Client Connection Tracker → "disconnected"]
 ├─ connecting (default)  [Initialize] ──exec──▶ Startup Gate ("gameplay")
 │                                                  [Client Go In Game]
 ├─ gameplay
 └─ disconnected
Why this shape: ClientGoInGame is [ExecuteNode(..., typeof(InitializeState))]. Only StartupGate owns BlobArray<BlobPtr<ExecutionHeader<InitializeState>>> blocks. Only Initialize runs a connected gate from a Canopy state. So connecting cannot reach gameplay until every gate block completes — and GoInGame only completes when the server has marked the connection in game.

One-tick script

ClientAppStateSystem.OnUpdate
  connection = {
    ConnectionEvents = NetworkStreamDriver.ConnectionEventsForTick,
    IsHost = World.IsHost(),          // false for split Client/Server worlds
    LocalConnection, HasNetworkId, IsInGame from singleton NetworkStreamConnection
  }
  execution = executor.GetExecution(ref state)
  execution.Context.Connection = connection      // AFTER GetExecution (value copy)
  execution.Context.CommandBuffer = EndSim ECB
  executor.Run → graph root/update...

Tracker (on root every relevant update)
  fold events into ClientConnectionSnapshot in GroveState
  if Disconnected → CanopyGoTo("disconnected")

If current state == connecting
  Initialize → StartupGate
    GoInGame(ref InitializeState):
      if !known || !NetworkId || disconnected → IsCompleted=false
      if !IsInGame:
        if identity not yet requested:
          AddComponent<NetworkStreamInGame> (if !host)
          CreateRPC<GoInGameRequest>
          remember identity in graph state
      IsCompleted &= IsInGame
    if all blocks complete → CanopyGoTo("gameplay")

Asmdef trap (real bug fixed)

Runtime Daggertooth.asmdef must not reference BovineLabs.Nerve.State.Authoring (UNITY_EDITOR-constrained). That ref vanishes in player builds — same family as defineConstraints traps. Split like the sample: runtime / .Authoring / .Editor, each carrying the constraints its deps demand.

Approval side note

ConnectionApprovalServerSystem skips JWT only when World.IsServer() is false (pure local world). A separate ServerWorld in one process is still a server — so approval on would hit Unity Authentication. LocalApproveConnectionSystem stays; justification verified.
