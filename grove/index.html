How Grove works

Eight Archify maps, two narration depths. The diagrams are the lesson; the voice tracks walk you through them without turning this page into a textbook.

Open explore Fun track first (plain language) → Serious track (types & call paths). Hover diagram boxes for short lines. About 25–40 minutes if you listen to both tracks.
What “Fun” and “Serious” mean here. Same eight diagrams. Fun names things you can picture (brick, robot, door book, backpack). Serious uses the real identifiers you will search for in the package (GraphImpl, ExecutionGenerated, GroveState, bake entry rules). Do not skip Fun if you are new — Serious assumes you already saw the shape.

Point at any box and it explains itself. Click for the reasoning. Guided tour optional.

Study order

  1. In the player, leave Fun selected. Press Play lesson and let chapters advance.
  2. Finish lessons 01 → 08 on Fun (the player can auto-advance lessons).
  3. Switch to Serious and repeat. You should recognize every box before the jargon lands.
  4. When Serious still feels fuzzy on one map, open that map alone (table below) and use Archify’s chapter rail (P).

Maps

#MapYou should be able to explain…
01 Toy machine Draw vs bake vs play; why the source asset is not the runtime brick
02 Draw → bake → play Import pipeline; single Input→execution entry rule; variants strip at bake
03 One frame GraphImpl / GraphExecution / SetChunk / Execute ownership
04 Brick anatomy Header + inline payload; Type int; blob pointers as edges
05 Door book Source generator fills your context switch; brick only stores Type
06 Push vs pull Execute push vs Calculate pull; GroveState as live memory
07 Make a toy Four pieces of a custom node and how they meet at bake/dispatch
08 Blob secret Why GraphData is easy: no edge table, BlobPtrs as ports, shared immutable blob, context holds life

After both tracks

  • You can point at each assembly and say what it owns (Editor / Authoring / Runtime).
  • You can write the OnCreate / OnUpdate skeleton around GraphImpl without guessing.
  • You can add a custom execution node without cargo-culting a fourth copy of “auth.”
  • You know where inputs actually live (entity GroveState, not stack args on Root).
